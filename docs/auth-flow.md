# 🔒 Аутентификация, сессии и подтверждение email

Система безопасности построена на базе модуля `nuxt-auth-utils`, реляционной модели PostgreSQL (`users` + `roles`), **Redis** для временных токенов и **Nodemailer** для почтовых рассылок.

## Жизненный цикл пользователя

1. **Регистрация (`POST /api/auth/register`)**:
   - Пользователь передает имя, email и пароль (плюс опциональный аватар).
   - Создается запись в таблице `users` с флагом **`is_active: false`**.
   - Генерируется криптографически стойкий токен (`randomBytes`).
   - Токен сохраняется в **Redis** с ключом `verify:<token>` и TTL **24 часа (86400 сек)**.
   - Через Nodemailer (SMTP Mail.ru) отправляется письмо со ссылкой подтверждения.
   - Сессия **не создается**, вход на сайт заблокирован.

2. **Подтверждение почты (`GET /api/auth/verify?token=...`)**:
   - Пользователь кликает по ссылке в письме, которая ведет на бэкенд-эндпоинт.
   - Сервер ищет токен в Redis. Если токен найден, извлекается `user_id`.
   - В базе данных статус пользователя обновляется: **`is_active: true`**.
   - Токен удаляется из Redis (защита от повторного использования).
   - Создается защищенная куки-сессия через `setUserSession`.
   - Происходит редирект пользователя на главную страницу сайта с активным аккаунтом.

3. **Вход в систему (`POST /api/auth/login`)**:
   - Проверяется совпадение хеша пароля через `bcryptjs`.
   - Проверяется флаг `is_active` (неподтвержденные аккаунты получают ошибку доступа).
   - При успешной проверке создается сессия.
