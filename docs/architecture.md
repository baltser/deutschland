# Архитектура проекта (DNZ Architecture)

Данный документ описывает системную архитектуру, структуру каталогов и принятые паттерны разработки в проекте **DNZ** на базе **Nuxt 4**.

---

## 1. Общий стек технологий
* **Фреймворк:** Nuxt 4 (Vue 3, Composition API)
* **Интерфейс & UI:** Tailwind CSS, Nuxt UI Kit
* **Управление состоянием:** Pinia (`app/stores/`)
* **Авторизация и сессии:** `nuxt-auth-utils` + **uCaller.ru** (flash-call верификация номеров телефонов)
* **Серверная часть:** Nitro API (`server/api/`)
* **База данных:** PostgreSQL + Prisma ORM
* **Файловое хранилище:** MinIO (объектное хранилище для аватаров и медиа)
* **Кэш и временные данные:** Redis

---

## 2. Структура каталогов и зоны ответственности (`app/`)

Клиентская часть построена по модульному принципу:

```text
app/
├── components/          # UI-компоненты по доменам
│   ├── admin/           # Административная панель (UserTable, RoleEditModal)
│   ├── auth/            # Авторизация (Card, AvatarUpload)
│   ├── user/            # Пользовательские элементы (UserAvatar)
│   └── app/             # Глобальные элементы (Header, Logo)
├── composables/         # Переиспользуемая бизнес-логика
├── stores/              # Глобальные состояния Pinia
├── pages/               # Файловый роутинг (auth/, admin/, profile/)
├── layouts/             # Каркасы страниц (default.vue, auth.vue)
└── types/               # TypeScript интерфейсы
```
## 3. Серверная архитектура (server/)

Серверная логика реализована на Nitro и разбита по доменам:
```Plaintext

server/
├── api/
│   ├── auth/            # login.post.ts, register.post.ts, send-code.post.ts (uCaller интеграция)
│   ├── users/           # [id]/avatar.post.ts (обработка multipart, загрузка в MinIO)
│   ├── admin/           # Управление пользователями и ролями
│   └── files/           # Проксирование и раздача файлов из MinIO
├── plugins/
│   └── startup.ts       # Инициализация при старте (проверка БД, Redis, MinIO, сидирование ролей и админа)
└── utils/               # Системные синглтоны (prisma.ts, minio.ts, redis.ts, roles.ts, adminUser.ts)
```
``Автоматическая инициализация (Startup Plugins)``

При старте сервера плагин startup.ts последовательно проверяет внешние сервисы и выполняет первичное сидирование:

*  Подключение к PostgreSQL и проверка критических таблиц.

*  Проверка и автоматическое создание базовых ролей через ensureDefaultRoles().

*   Создание дефолтного администратора (при его отсутствии) через ensureDefaultAdminUser().

*   Инициализация почтовых шаблонов ensureDefaultEmailTemplate().

*   Проверка доступности Redis и MinIO.

## 4. Управление состоянием (Pinia Stores)

Клиентское состояние вынесено в изолированные Pinia-сторы (`app/stores/`):
* **`adminUsers` (`adminUsers.ts`):** Управление сотрудниками, их ролями, статусами активации и аватарами с оптимистичным обновлением локального стейта.
* **`adminClients` (`adminClients.ts`):** Загрузка и отображение клиентов системы вместе с привязанными объектами (`addresses`).
* **`adminAddresses` (`adminAddresses.ts`):** Управление списком физических объектов/адресов и привязанными к ним жильцами.
