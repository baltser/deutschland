# Архитектура проекта (DNZ Architecture)

Данный документ описывает системную архитектуру, структуру каталогов и принятые паттерны разработки в проекте **DNZ** на базе **Nuxt 4**.

---

## 1. Общий стек технологий
* **Фреймворк:** Nuxt 4 (Vue 3, Composition API)
* **Интерфейс & UI:** Tailwind CSS, Nuxt UI Kit
* **Управление состоянием:** Pinia (`app/stores/`)
* **Авторизация:** `nuxt-auth-utils` (сессионная аутентификация)
* **Серверная часть:** Nitro API (`server/api/`)
* **База данных:** PostgreSQL + Prisma ORM
* **Файловое хранилище:** MinIO (объектное хранилище для аватаров и медиа)

---

## 2. Структура каталогов и зоны ответственности (`app/`)

Клиентская часть построена по модульному принципу:

```text
app/
├── components/          # UI-компоненты по доменам
│   ├── admin/           # Административная панель (UserTable, RoleEditModal)
│   ├── auth/            # Авторизация (Card, пассивный AvatarUpload)
│   ├── user/            # Пользовательские элементы (активный UserAvatar)
│   └── app/             # Глубокие глобальные элементы (Header, Logo)
├── composables/         # Переиспользуемая логика (useAuth.ts)
├── stores/              # Глобальные состояния Pinia (adminUsers.ts)
├── pages/               # Файловый роутинг (auth/, admin/, profile/)
├── layouts/             # Каркасы страниц (default.vue, auth.vue)
└── types/               # TypeScript интерфейсы
```
Паттерны компонентов аватара:
---
    auth/AvatarUpload.vue (Пассивный): Используется при регистрации. Не делает сетевых запросов самостоятельно, возвращает объект File в родительскую форму для передачи через FormData.

    user/UserAvatar.vue (Активный): Используется в админке и профиле. Самостоятельно управляет userId, отправляет файл на сервер (/api/users/[id]/avatar), показывает процесс загрузки и генерирует событие @updated.
---
## 3. Серверная архитектура (server/)

Серверная логика реализована на Nitro и разбита по доменам эндпоинтов:
```Plaintext
server/
├── api/
│   ├── auth/            # login.post.ts, register.post.ts
│   ├── users/           # [id]/avatar.post.ts (обработка multipart, загрузка в MinIO)
│   ├── admin/           # Управление пользователями (users.get, [id].patch)
│   └── files/           # Проксирование и раздача файлов из MinIO
└── utils/               # Системные синглтоны (prisma.ts, minio.ts)
```
Поток загрузки и сохранения аватара:

    Клиент выбирает файл через <UserAvatar>.

    Файл отправляется на /api/users/[id]/avatar как multipart/form-data.

    Сервер валидирует тип и размер, сохраняет оригинал в MinIO бакет (dnz-uploads) и записывает относительный путь (avatars/...) в модель User через Prisma.

    При обновлении ролей в админке (RoleEditModal) актуальный путь к аватару синхронизируется с базой данных, исключая его затирание.
